# Робоход — командуй роботом

Учебный демопроект по информатике для **5–7 классов**. Ученик собирает программу из блоков, запускает робота, разбирает ошибку и пробует снова. **20 уровней, 34 учебных поля и песочница** для собственных задач.

**[Открыть тренажёр](https://heartcatched.github.io/robot-lab/)** · [Исходники](https://github.com/heartcatched/robot-lab)

Сайт уже опубликован. Для использования достаточно открыть ссылку: запускать терминал, устанавливать Node.js или держать компьютер автора включённым не нужно.

## Что можно освоить

| Уровни | Практика |
| --- | --- |
| 1–4 | Последовательность команд, обход препятствий, исправление ошибок |
| 5–8 | Повторение команд и действия после цикла |
| 9–10 | Закрашивание клеток и рисунок в цикле |
| 11–12 | Условия «если», ветки «то» и «иначе» |
| 13–16 | Цикл «пока», проверка свободного пути, поиск прохода |
| 17–20 | Алгоритмы А/Б/В, вызовы из цикла, разбиение задачи на части |

Все уровни доступны сразу. У уровней 11–16 и 20 по три варианта поля: одна программа должна решить каждый. Проверка проводится после всей программы. Пропущенные и лишние закрашенные клетки отмечаются на поле; при ошибке движения подсвечивается преграда или край.

Можно выполнять программу целиком, поставить на паузу или двигаться по одному шагу. Текущий блок и соответствующая строка кода КуМир подсвечиваются. Параметры меняются прямо в блоках; отмена возвращает до 50 правок отдельно для каждого уровня и песочницы. Результаты, попытки и использование подсказок при отмене не меняются.

На телефоне поле находится над прокручиваемым редактором, кнопки запуска — снизу, команды открываются отдельной панелью. Для длинных циклов и вложенных условий нажмите «Развернуть»: редактор займёт почти весь экран. «К полю» вернёт обычный вид; при запуске или выполнении по шагам поле возвращается автоматически. После добавления команды редактор прокручивается к месту вставки. При повторном посещении открывается последний уровень с сохранённой программой; запуск остаётся ручным.

## Песочница и сохранения

- Поля 5–8 строк и столбцов: старт, станция, камни, стены, начальная и целевая закраска.
- «Сохранить» записывает черновик в браузер; меню «Проект» позволяет скачать или открыть JSON с полем и всей программой.
- «Поделиться» создаёт ссылку с названием, полем и целью. Решение и алгоритмы в неё не включаются. Открытие задачи не перезаписывает личный черновик.
- Прогресс хранится в браузере. Аккаунтов, серверной базы и автоматической синхронизации нет.
- Для переноса на другое устройство: счётчик прогресса → «Перенести все сохранения» → «Скачать все сохранения». На другом устройстве — «Восстановить из файла». Файл содержит результаты, программы, сохранённый черновик и текущий незавершённый проект отдельно. Замена требует явного подтверждения.
- Поддерживается загрузка ранее сохранённых версий данных. При недоступном хранилище играть можно; данные можно выгрузить в файл.

## Как работает публикация

GitHub Pages раздаёт содержимое `dist/`, а программы робота выполняются в браузере ученика. Постоянный сервер приложения и платный API не нужны.

Настройка находится в [`.github/workflows/pages.yml`](.github/workflows/pages.yml). Изменения кода в ветке `main` запускают GitHub Actions: установка инструментов, проверки логики, Chromium/WebKit, затем публикация. При ошибке тестов обновление не выпускается. Изменение только Markdown-документов не запускает публикацию сайта.

Источник в Settings → Pages — **GitHub Actions**. Пользователю сайта ничего запускать не требуется. Подробнее: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [публикация через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Локальный запуск для разработки

Нужен Node.js 18+; в CI используется Node.js 22. Для просмотра установка пакетов не требуется:

```bash
npm run dev
```

Откройте `http://127.0.0.1:4173/`. Альтернатива: `python3 -m http.server 4173 --directory dist`. Через `file://` JavaScript-модули не работают, поэтому нужен HTTP-сервер.

Для проверки пути, как на GitHub Pages:

```bash
BASE_PATH=/robot-lab/ npm run dev
# http://127.0.0.1:4173/robot-lab/
```

## Проверки

```bash
npm ci
npx playwright install --with-deps chromium webkit
npm run check
npm run test:e2e
```

`check` проверяет синтаксис и 43 проверки логики: модель/миграцию данных, исполнитель и все учебные поля, файлы/ссылки, резервные копии/историю правок. На Node.js 18 итоговая сводка может показывать четыре тестовых файла вместо отдельных проверок.

35 сценариев Playwright проверяют пользовательские действия, весь маршрут, файлы и ссылки, резервные копии, отмену, клавиатуру и адаптивность, включая редактирование длинных вложенных программ. Chromium: 320×568, 360×740, 390×844, 768×1024, 1366×768 и 1440×900; WebKit: 390×844. Локальные тесты работают под `/robot-lab/` и сами запускают сервер.

Для публичного сайта: `BASE_URL=https://heartcatched.github.io/robot-lab/ npm run test:e2e`. Подробности и ограничения — в [QA.md](QA.md).

Дополнительно автор проекта вручную протестировал сайт на физических телефонах.

## Что находится в репозитории

| Файлы | Назначение |
| --- | --- |
| `dist/` | Сам сайт: HTML/CSS/JS, робот, локальный шрифт и его лицензия. Это исходный код, сборка не требуется |
| `tests/`, `playwright.config.js` | Проверки логики и пользовательских сценариев |
| `scripts/serve.mjs` | Сервер локального просмотра |
| `package.json`, `package-lock.json` | Команды проекта и зафиксированные версии инструментов тестирования |
| `.github/workflows/pages.yml` | Автоматическая проверка и публикация |
| `README.md`, `QA.md` | Описание проекта, запуск и результаты проверки |

`node_modules/`, отчёты Playwright, временные снимки и `.git/` не нужны в архиве исходников. Репозиторий содержит всё необходимое для запуска и проверки.

## Ограничения и развитие

До 80 блоков, трёх вложенных управляющих конструкций, 1–10 повторений и 1000 операций за запуск. Алгоритмы А/Б/В без параметров и рекурсии. Код КуМир только показывается и копируется: текстового ввода и импорта `.kum` нет.
